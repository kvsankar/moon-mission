# Orion Procedural Model

Original implementation date: April 3, 2026.

## Purpose

Describe the configurable Orion-like spacecraft model generated in code without
a runtime GLTF dependency. Visual-source history is preserved in
[Orion Visual References](../../research/rendering/orion-visual-references.md).
Future work is tracked in
[Orion Model Follow-Ups](../../plans/implementation/orion-model-followups.md).

## Design Choice

The Orion model is procedural because it provides deterministic startup, no
geometry download, direct proportion/material tuning, and compatibility with
the existing renderer and layer model.

`SpacecraftRenderer` registers both `orion` and `orion-procedural`; both invoke
`createProceduralOrion(options)`. Unknown plugin names warn and fall back to the
simple craft.

## Composition

The model is a group of Three.js primitives:

1. Crew-module frustum.
2. Crew-module adapter ring.
3. Forward docking hatch ring and center disk.
4. Side window/sensor pods.
5. European service-module cylinder with ring banding.
6. Aft skirt and engine-nozzle silhouette.
7. Four articulated solar wings at 90-degree spacing, rotated as a 45-degree
   set; each wing has three panel segments and hinge details.

The procedural geometry receives a fixed 90-degree attitude offset around the
Y axis so the plugin model aligns with runtime spacecraft attitude conventions.

## Materials

- Capsule: blue-gray metallic material.
- Adapter and service module: light gray/white materials.
- Nozzle and structural details: darker metallic materials.
- Solar wings: light segmented panels with frame, hinge, and inset accents.

## Plugin Options

| Option | Behavior |
| --- | --- |
| `scale` | Positive model scale; defaults to `1` |
| `autoTrackSun` | Enables one-degree-of-freedom solar tracking unless explicitly `false` |
| `capsuleColor` | Capsule material color override |
| `adapterColor` | Adapter material color override |
| `serviceColor` | Service-module material color override |
| `nozzleColor` | Nozzle material color override |
| `windowColor` | Window/sensor material color override |
| `panelColor` | Solar-panel material color override |
| `panelFrameColor` | Solar-panel frame/hinge color override |

Artemis II currently uses:

```json
"spacecraftModel": {
  "enabled": true,
  "plugin": "orion-procedural",
  "options": {
    "scale": 0.7
  }
}
```

The maintained owner is `assets/artemis2/data/config.json5`; runtime consumes
the compiled `config.json` generated by `npm run configs:compile`.
Mission-level and craft-level model configuration is resolved by spacecraft
actions before plugin creation.

## Solar Array Tracking

When enabled, each solar wing keeps a tracker containing its static base-frame
inverse and current hinge angle. Runtime supplies the live craft-to-Sun
direction. The renderer transforms that direction into craft and wing-base
coordinates, computes one hinge angle, and applies a strict one-degree-of-
freedom rotation.

Invalid or zero Sun directions preserve the last valid tilt. GLTF and simple
models disable the procedural Orion tracker state.

## Runtime Characteristics

- Geometry and materials are generated during scene setup.
- No runtime craft-model download is required.
- Model objects use spacecraft render layer 1.
- The craft retains existing visibility, axes-helper, drone, and disposal
  behavior.

## Code Ownership

- `src/platform/js/rendering/spacecraft-renderer.js`: registry, procedural
  geometry, options, attitude offset, solar tracking, fallback, and disposal.
- `src/platform/js/app/spacecraft-actions.js`: mission/craft configuration
  resolution and creation path.
- `src/platform/js/controllers/animation-3d-controller.js`: live Sun-direction
  forwarding.
- `src/platform/js/core/domain/mission-config.js`: accepted model config key.
- `assets/artemis2/data/config.json5`: authored Artemis II plugin selection.

Controller tests verify Sun-direction forwarding. Direct plugin, option,
geometry, fallback, and configuration-precedence coverage remains in the
follow-up plan.
